# Text Transmorph — 点阵粒子文字变形工具 设计文档

- 日期：2026-06-19
- 状态：已确认，待转实施计划

## 1. 目标

做一个把中文 / 英文文字「解离、变换成另一些文字」的视觉工具，效果对标 `effect/640.gif`：文字以点阵（halftone）呈现，切换时所有点散开成粒子云、再重组成下一段文字，循环往复。

工具需同时满足：

- **本地构建**：`npm run dev` 实时预览、可玩参数。
- **线上部署**：`npm run build` 产出静态站，可部署到 Vercel / Netlify / Cloudflare Pages / GitHub Pages。

核心产出 = **交互式网页工具 + 动画文件导出**，两者都要。

## 2. 参考效果分析

`effect/640.gif`：640×260，50 帧，每帧 80ms。

- 帧 0：「灵感指南」点阵呈现
- 帧 16：变成「AI时代的」
- 帧 32：所有点散开成粒子云（解离态）
- 帧 49：粒子重新聚合回「灵感指南」

本质是**点阵粒子文字变形（particle text morph）**：每段文字被采样成一组目标点，切换时粒子从文字 A 的位置飞散、再重组到文字 B 的位置。点可为方块或圆点。

## 3. 技术选型

**纯前端单页应用** —— Vite + TypeScript + Canvas 2D。无后端，渲染与导出全部在浏览器内完成。

- 选 Canvas 2D 而非 WebGL：示例规模几百到几千个点，2D 够用、简单、易调试。
- 绘制抽象成接口，将来需要上万粒子可替换为 WebGL 渲染器而不动上层逻辑。

## 4. 内容模型（两种模式都支持）

- **多段轮播**：输入文字列表（如「灵感指南」→「AI时代的」→…），依次解离重组、循环。对标 GIF。
- **单段呼吸**：只输入一段文字，做「粒子散开 → 重新聚成同一段文字」的呼吸式循环。

二者共用同一套粒子引擎；单段呼吸 = A→A 的过渡加散开。

## 5. 模块拆分

每个单元单一职责、通过明确接口通信、可独立理解与测试。

| 模块 | 职责 | 依赖 | 可单测 |
|---|---|---|---|
| `sampler` | 把一段文字（中/英）渲染到离屏 canvas，按网格采样像素，输出"该亮的目标点"坐标集。处理任意 web 字体 | 离屏 canvas | 坐标网格逻辑部分可纯测 |
| `particles` | 维护粒子池。文字 A→B 切换时给每个粒子分配新目标点，沿"先散开成云、再聚合"路径插值运动。**纯数学，不碰 DOM** | 无 | 是 |
| `easing` | 缓动曲线、散开强度随时间的包络函数。纯函数 | 无 | 是 |
| `renderer` | 把粒子按 方块/圆点、颜色、大小 画到主 canvas | Canvas | 否（视觉冒烟） |
| `sequencer` | 驱动文字序列：停留时长、过渡时长、循环。单段呼吸 = A→A+散开 | 无 | 是 |
| `config` | 类型化、可扩展的参数对象（核心参数现做，预留扩展位）+ 响应式通知 | 无 | 是 |
| `ui` | 富控制面板，双向绑定 config | config | 否 |
| `exporters/gif` | gifenc 逐帧编码下载 | canvas 帧 | 否 |
| `exporters/webm` | MediaRecorder 录制 | canvas 流 | 否 |
| `exporters/mp4` | ffmpeg.wasm 懒加载转码 | 帧/webm | 否 |
| `main` | requestAnimationFrame 串联全部 | 全部 | 否 |

**关键设计点 — 确定性渲染**：动画循环支持"给定时间 t 渲染该帧"的纯函数式步进。预览用实时时间驱动；导出以固定帧率逐帧精确步进，不受实时性能波动影响。预览与导出共用同一套渲染逻辑，保证一致。

## 6. 粒子变形算法

1. 每段文字 → 经 `sampler` 得到目标点集 `P`，按 `phrase + 网格密度` 缓存，不重复采样。
2. 粒子总数 = 各 phrase 目标点数的最大值；过渡期多余粒子藏到屏外 / 透明。
3. A→B 过渡：每个粒子路径 = `lerp(A点, B点)` 叠加一个**中途达峰的散开偏移**（峰值在过渡中点）。于是粒子先飞散成云（对应帧 32），再收拢成新字。散开强度、随机度可调。
4. 停留期：粒子静止在组装好的文字上，可选微抖动呼吸感。

粒子→目标点的分配策略：MVP 用稳定的空间排序分配（减少视觉跳变），接口预留可替换为最近邻 / 随机分配。

## 7. 可调参数（config，设计为可扩展）

文字列表、模式（轮播/呼吸）、背景色、点色（单色/渐变）、点形状（方/圆）、点大小、网格密度、点间距、过渡时长、停留时长、缓动曲线、散开强度、随机度、字体。

新增参数只需扩展 config 定义与 ui 绑定，不需重构引擎。

## 8. 导出

- **GIF**：`gifenc` 现代快速编码，逐帧抓取 → 下载。
- **WebM**：`canvas.captureStream()` + `MediaRecorder`，浏览器原生、零依赖。
- **MP4**：`ffmpeg.wasm` 懒加载（~30MB，仅点击 MP4 时下载），把帧 / WebM 转码成 MP4。

所有导出走固定帧率逐帧抓取（第 5 节的纯函数步进），保证导出与预览一致。

## 9. 错误处理

- 字体加载失败 → 回退系统字体。
- MediaRecorder 不支持的 mime → 特性检测后禁用对应按钮并提示。
- ffmpeg.wasm 加载失败 → 优雅降级为只提供 WebM。
- 空文字 / 超长文字 → 截断并提示。
- 网格过密导致粒子过多 → 警告并限制粒子上限。

## 10. 测试策略

遵循 TDD。把纯数学（网格采样坐标逻辑、粒子插值、缓动、点分配、sequencer 时间线）与 canvas I/O 分离：

- **Vitest 单测**：`particles`、`easing`、`sequencer`、`config`、`sampler` 的网格坐标逻辑。
- **可选 Playwright 视觉冒烟**：加载页面、跑动画、抓一帧确认渲染正常。

## 11. 部署

- 构建：`npm run build` → `dist/` 静态资源。
- 目标：Vercel / Netlify / Cloudflare Pages / GitHub Pages 任一。
- GitHub Pages 需注意 `base` 路径配置；提供一份部署说明。

## 12. 明确不做（YAGNI）

- 不做后端 / 账号 / 存储。
- 不做服务端渲染或服务端转码（MP4 用浏览器内 ffmpeg.wasm 解决）。
- MVP 不做 WebGL 渲染器（仅预留接口）。
- 不做多语言 UI 国际化（界面中文即可）。
